# Step 4 recovery status

Target: invite-only testnet beta with disposable funds. This branch adds a
member-run, relay-free recovery exit at `poc/wallet/recovery_tool.py`. Two
members bring only their own final card and 24 words, choose new unlock
passphrases, review and approve a sweep, and send it to a new vault address.
The ordinary member app creates and backs up the destination vault.
The existing setup and payment binaries are still regtest-only, so this is
not yet evidence of an invite-only testnet deployment.

## Evidence run in this worktree

```sh
cd poc
python3 -W error::ResourceWarning -m unittest -v wallet/test_recovery_tool.py
python3 -W error::ResourceWarning -m unittest wallet/test_member_app.py wallet/test_recovery_tool.py
cargo test
```

Observed: the recovery suite passed 7 tests; the combined member app and
recovery suite passed 24 tests; `cargo test` passed 111 tests across 17 suites,
with zero failures.

The Python test uses fake regtest command executables to exercise the full
guided orchestration. It covers lost device, lost passphrase, relay outage,
departure to a different vault address, two distinct approvals, and refusal
of a provisional card. The Rust sweep test checks the all-notes amount and
one-to-eight-note limit. Existing Rust tests check real card restoration,
two-note candidate construction, and the signer pipeline. These tests do not
prove the new tool can broadcast and mine a real transaction.

## Live regtest checks still required

This worktree has no isolated THS CLI or owned THS regtest instance. Other
Docker regtest containers were running on this machine, but they belong to
another QA run and were not changed. Before marking this member journey
verified for beta, run each of these with a dedicated THS regtest node and
real final cards generated by the member app:

| Scenario | Required live observation |
| --- | --- |
| Lost device | Delete both old member data roots; use only their final card files and written words in the guided tool; see a mined sweep in the destination vault. |
| Lost passphrase | Use new passphrases without reading the originals; see the same source address and a mined sweep. |
| Relay outage | Stop both payment relays and setup courier; keep the regtest node available; approve and mine a sweep. |
| Member departure | Create and back up a new vault with the continuing roster; sweep every source note to its different receive address; confirm source balance is zero and destination balance equals sweep amount. |

The tool stops before signing when the source has more than eight unspent
notes. Both restored shares coexist temporarily on the recovery computer, so
members must trust that computer during the exit. A hard crash can leave its
private temporary directory behind; inspect and remove it after recovering.
Members must compare the reviewed recipient with the new vault's address;
the tool cannot prove that a manually entered address belongs to that vault.
If a broadcast is not mined yet, the tool prints its transaction ID and
removes the temporary signing files; use the new vault's chain scan to confirm
receipt before treating the exit as complete.
The underlying local signing path still has volatile nonce state and is only
appropriate for this disposable-funds regtest beta.
